# I-5 Buddy architecture (v2)

A static PWA, no build step, no dependencies. Plain ES modules. Hosted on GitHub Pages. Targets iOS Safari 15+ and
Chrome on Android 100+, and must keep working offline (except live data). Everything stays on the phone; the only
network calls are the static files, opt-in live data (weather.gov, Caltrans, and `/api/traffic` on i5.dominares.org:
CHP incidents and Caltrans lane closures for all of I-5, so the request carries no location), feedback the user sends
(`/api/feedback`), Wikimedia photos already in `img/`, and map pictures (terrain and basemap tiles) only while the 3D
map is open. The server side is the Cloudflare Worker `i5-buddy` (source outside this repo, see README).

```
index.html            markup and containers (its head keeps the browser's install offer for the Install app buttons)
app.css               core styles and design tokens (night = default, day = [data-theme="light"])
css/<module>.css      one stylesheet per module, using ONLY the tokens from app.css
data/i5.js            window.I5DATA (generated by tools/build.py; never edit by hand)
js/store.js           settings, live state S, localStorage helper, event bus

js/geo.js             GPS -> corridor mile, bearings, sun altitude

js/main.js            boot, GPS/demo/manual, Drive + Ahead screens, settings, offline, Install app, module loading
js/live.js            MODULE: traffic (CHP + Caltrans closures), weather, alerts, chain controls, freeway message signs, live cameras
js/map.js             MODULE: interactive map of the whole road
```

## Scope: which stretch of I-5

The app covers the states listed in `SCOPE` in `tools/build.py`: `["CA"]` since 2026-11-11, so the road runs from
the Mexico border at San Ysidro to the Oregon line, 797 miles. The data says so itself (`data.SCOPE`, `data.STATES`,
`data.MAX_M`, `data.ENDS`), and code must read it from there instead of hard-coding it:

- Never write "Canada", "Mexico to Canada", "1,381 miles", Oregon or Washington examples, or WSDOT/TripCheck into
  user-facing text. Use `ENDS.S.short` / `ENDS.N.short` ("Mexico" / "Oregon") and `ENDS.S.long` / `ENDS.N.long`
  ("the Mexico border" / "the Oregon line"), `Math.round(MAX_M)`, `STATES[i].name`, or plain California wording.
- Hide what does not apply: anything that needs a state that is not in `STATES` (a three-state badge, an Oregon road
  link, Washington cameras, state headings or a state-line welcome when there is one state).
- `SCOPE = ["CA", "OR", "WA"]` in tools/build.py rebuilds the whole road (north end: the Canadian border), and the app
  must then cover it again without code changes.

## Units and directions

- `m` = corridor mile: miles from the Mexico border along northbound I-5, 0 to `data.MAX_M` (796.97, the Oregon line).
  In California it is the exit number. When the build covers more states, each one's exit numbers continue from the
  previous state's end: CA 0 to 797, OR 797 to 1105 (OR exit = m - 797), WA 1105 to 1382 (WA exit = m - 1105).
  Use `data.localMile(m)` and `data.exitName(st, ref)`.
- The road line starts at m 0.29 (`ROUTE[0]`, the San Ysidro port of entry) and ends at `MAX_M`.
- `S.dir` is `"N"` (toward `ENDS.N`, the Oregon line, m increasing) or `"S"` (toward Mexico).
- A place's `side` is `1` (right side when driving north), `-1` (left when driving north) or `0` (on the road / both).
  Use `data.sideWord(place, S.dir)` to get `"left" | "right" | ""`.
- `data.aheadOf(m, dir, x)`: signed miles from m to x in the travel direction (positive = still ahead).

## Off the road, and the end of the road (main.js)

Two GPS fixes in a row more than 1.2 miles from I-5 (or 1.5 times the fix's accuracy) set `S.offRoute`: the marker
stays at the last mile on the road, the pill says OFF I-5 and the status line "Not on I-5 right now. Narration
paused." The narrator says nothing while `S.offRoute` is true, and modules must not either (except what the user asks
for). If that fix is past an end of the covered road (beyond the latitude of the line's last point, with the last mile
on the road within 3 miles of that end), the pill says THE END, the status line "Past the Oregon line. Narration
paused." (`Past ${ENDS.N.long}`; "Past the Mexico border" at San Ysidro), the next card "You made it to the Oregon
line", and, if this GPS session drove there, it says once "That's the Oregon line, the end of the road for I-5 Buddy.
Thanks for riding along." (speech id `end-of-road`). A fix that bounces back near the line does not repeat it; only
driving back onto the road more than 3 miles from that end lets it be said again. Ending the trip clears `S.offRoute`.

## The module contract

Each module file exports `init(api)` and is loaded by main.js with a dynamic import. If a module throws, the rest of
the app keeps working, so a module must never assume another module exists (check `api.live`, `api.play`, etc.).

```js
api = {
  S,            // live state: {mode, m, dir, speed, heading, lat, lon, offRoute, accuracy, stamps, dest}
  settings,     // {narr, zoneNarr, chat, lead, rate, voice, cats:Set, kid, chime, live: null|true|false, theme}
  saveSettings, // persist settings and emit "settings"
  bus,          // bus.on(evt, fn) -> unsubscribe; bus.emit(evt, data)
  store,        // store.get(key, fallback) / store.set(key, value) / store.del(key)  (localStorage, "i5b:" prefix)
  voice,        // voice.say(text, {id, prio 0-3, now, chime: true|"alert"|"success", check, onstart, onend}) -> Promise<bool spoken>
                //   now:true interrupts and goes first, but KEEPS queued urgent items (prio >= 2) and re-queues an
                //   interrupted urgent item after itself; lower-prio queued items are dropped (resolve false).
                //   hold(true|false): pause all speech (mic open); the current item is re-queued at the front, nothing
                //   is lost, and say({now}) while held just goes to the front. stop(): user's "be quiet", clears all.
                //   chime(kind); unlock(); isSpeaking(); currentId(); queued(); repeat(); prune(); isHeld()
  narrator,     // upcoming(m, dir, cats, range), announceText(p, d), tellMore(p), hear(p), look(side), whereAreWe(), howFar(dest), tellServices(kind), nextOne()
  data,         // everything exported by js/data.js
  geo,          // everything exported by js/geo.js
  ui: { $, el, toast, go(tab), openSheet(sheetEl), closeSheet(), photo(place, "hero"|"thumb"|"full"), placeSheet(place), queueRender() },
  setPosition,  // setPosition(m, {speed, dir, offRoute, jumped}) (main uses it; modules normally don't)
  setMode, startDemo, startGps, stopAll, // for tests and the E2E harness
}
```

A module may attach its own public API to `api` (for example `api.live = {weatherText}`) for other modules and voice commands.

### Events on `api.bus`

| event | payload | when |
| --- | --- | --- |
| `pos` | `{m, prevM, dir, speed, offRoute, jumped}` | every position update (GPS fix, demo tick, manual move). `jumped` = teleport, not driving. |
| `mode` | `"off" or "gps" or "demo" or "manual"` | tracking mode changes |
| `trip:end` | `{}` | user ended a trip |
| `place:announce` | `{place, d}` | narrator queued a landmark announcement |
| `place:stamp` | `{place}` | a passport stamp was collected (drove past) |
| `place:look` | `{place}` | user asked "what's on my left/right" |
| `zone` | `{zone}` | entered a new landscape zone |
| `state:enter` | `{st}` | crossed a state line while driving (never while the data covers one state) |
| `tab` | tab name | user switched tab: drive, ahead, map, passport, play |
| `settings` | settings | settings changed |
| `speaking` | `{id, text}` or `null` | speech started / stopped |
| `passport:reset` | `{}` | user cleared the passport |
| `badge` | `{id, name}` | trip.js unlocked a badge |
| `place:sheet` | `{place, sheet, acts}` | main.js built a place details sheet; a module may append buttons to `acts` |
| `ride` | `{ride}` | ride.js: the user picked or changed their ride (see `api.ride`) |
| `ride:state` | `{state}` | ride.js: the ride started moving, rests awake, or fell asleep (`"moving"`, `"idle"`, `"sleepy"`) |
| `traffic` | `{incidents, updated, sources}` | live.js: a fresh traffic list arrived. `incidents`: every incident on the corridor (within 0.5 mi of I-5), each `{id, ids, source, kind, title, detail, lat, lon, started, dir, until, m, d, old, asOf}` (`d` = miles ahead in your direction, negative behind, null without a position; `old` = not current, either the whole list is old or it is a CHP item kept while CHP is not answering; `asOf` = when it was last confirmed, ms); `updated`: ISO string; `sources`: `{chp, caltrans}` |
| `live:update` | snapshot | live.js: a weather / alerts / chain refresh finished (roadahead.js redraws its forecast chips) |

### Traffic, Road ahead, feedback and share (2.5.0)

**Traffic (js/live.js).** While live info is on, the page is visible, the phone is online and the corridor mile is known, the
module fetches `GET /api/traffic` (relative on i5.dominares.org, else `https://i5.dominares.org/api/traffic`) now and every
2 minutes, with a 10 s timeout. It is its own fetch path: it never touches `fails`, the 2-minute weather rule or the
"Live info unavailable" footer, and a failure is silent (the last good copy stays, saved under `live:traffic`, dropped after
an hour). The request carries no location: the answer is the whole California I-5 list and the phone does the filtering.
`parseTraffic` normalises it (junk dropped, unknown `kind` becomes `other`, bad `dir` becomes null); `snapTraffic` snaps each
incident with `geo.locate`, keeps those within 0.5 mi of the line and folds the same event reported twice (same kind,
direction, words and place) into one entry that remembers every id (`ids`).
For the driver an incident counts when it is from 0.3 mi behind to 60 mi ahead and its `dir` is null or equals `S.dir`;
distance and filter are recomputed on every render, not only on fetch. Screen: the nearest two crashes, closures, hazards
or lane closures in `#liveAlerts` (ramp-only closures are left out of the strip; `--danger` for a crash or a closure that is
not a ramp, `--accent` otherwise), a "Traffic ahead" list at the top of `#liveBlock` (distance, "Northbound lanes", detail,
"until ...", tap for a sheet), and a source line `Traffic: CHP · Caltrans · updated 2 min ago` naming only the sources that
answered (class `lv-trsrc`, separate from the existing `lv-src`). Nothing ahead: "No crashes or closures reported ahead for
60 miles", said only when `sources.chp` is true, because CHP is the only source of crashes. When an answer has `chp: false`
(Caltrans answered), the block says plainly that crash reports (CHP) aren't answering right now and only Caltrans closures are
shown, never "no crashes"; the CHP items from the last good answer stay (for up to an hour), each marked old with its own age
("As of 12 min ago", from the last CHP answer, kept in `live:traffic` as `chpT`), dimmed, and never spoken. Data older than
15 min (judged from the server's `updated`, else the fetch time) says "(old)", dims the list and is
never spoken; offline says "Traffic needs a connection" and keeps the old list.
Speech: when a crash or a closure that is not a ramp first comes within 10 mi ahead it is said once (`traffic:<id>`, prio 2,
only with `settings.narr` on, `S.offRoute` false and fresh data) and the same words go to a toast. Several incidents within
2 miles of the first one are folded into the same sentence, and every id in it counts as said (cleared by `trip:end`).
API: `api.live.traffic()` (the corridor list with `m` and `d`), `api.live.trafficInfo()`, and
`api.live.weatherAlong()` -> `[{m, d, city, tempF, short, icon, emoji, t}]`, the forecast points the module already has
(no extra weather requests; empty unless live info is on and the mile is known).

**Road ahead (js/roadahead.js, `#roadAhead`).** An SVG elevation profile (the svg is `aria-hidden`; markers, labels and the
readout are HTML on top, positioned in percent) built from `data.ELEV` in the direction of travel: the next 50 miles or, with
the toggle, everything to `S.dest` (else the end of the road); the whole road before a trip (with no "you" marker then: there is no
position, and mile 0 would put the ride at the Mexico border). Grade = feet per mile / 5280 x 100
over a 3-mile window; climb and descent ignore wiggles under 30 ft (80 ft on long views). Colors: easy under 2%, moderate 2-4,
steep 4-6, very steep 6+ (`--nature`, `--accent`, `--hist`, `--danger`). It reads `api.live.weatherAlong()` and the `traffic`
event at draw time (so load order does not matter), uses `api.ride.svg()` for your marker when it exists (else a dot) and
redraws when the mile changes by half a mile, the direction flips, or the settings, traffic, weather, ride or destination
change. `api.roadahead.state()` gives the last drawing's numbers (used by tools/test-roadahead.html).

**Feedback (js/feedback.js).** Settings > About button opens `#feedbackSheet`: Name (optional), Email, Message (2000 characters,
counter) and a visually hidden `website` honeypot. Only on Send it POSTs `{name, email, message, version, website}` to
`/api/feedback` (same origin rule as traffic); the app version is read from `sw.js`'s `VERSION` line (constant `2.5.0` as a
fallback). States: sending, thanks, the server's own error words (text kept), offline (Send disabled), 15 s timeout. Name and
email are remembered after a send (`feedback:who`) and an unsent draft is kept (`feedback:draft`), both via `api.store`.

**Share (js/share.js).** The header button uses `navigator.share({title: "I-5 Buddy", text, url: "https://i5.dominares.org/"})`;
without Web Share, or when it fails for any reason except the user cancelling, `#shareSheet` opens (copy link, invite message,
Text message `sms:?&body=`, Email `mailto:`, Copy). A "Share" button is appended to each place sheet's `acts` through the
`place:sheet` event and shares `{place.name, first sentence, https://i5.dominares.org/#place=<id>}`. `#place=<id>` deep links
(on load and on `hashchange`) open `ui.placeSheet(place)` once and the hash is removed with `history.replaceState`; the old
github.io address's redirect already forwards `location.hash`.

### Rules for module code

- Only edit your own `js/<module>.js` and `css/<module>.css` (and your own test page `tools/test-<module>.html`).
  Never edit index.html, app.css, main.js, store.js, data.js, geo.js, voice.js, narrator.js or sw.js. If you need a core
  change, describe it precisely in your final report.
- Colors, fonts, radii only from the app.css tokens: `--bg --surface --surface-2 --line --fg --fg-2 --muted --sign --sign-fg
  --accent --accent-fg --link --shield --danger --ok --farm --hist --nature --town --stop --odd --st-ca --st-or --st-wa
  --display --mono --radius --shadow`. Both themes must look right (`:root` = night, `:root[data-theme="light"]` = day).
  (`--st-or` and `--st-wa` stay for when the build covers Oregon and Washington; they are fine as plain accent colors.)
- Scope: read the covered road from the data (see "Scope" above); no Canada, Oregon, Washington or 1,381-mile wording,
  and hide features that need a state the data does not cover.
- Mobile first: 360 to 600 px wide, touch targets at least 44 px, no horizontal page scroll, safe-area aware.
- Accessibility: real buttons, labels, `aria-pressed` for toggles, visible focus, `prefers-reduced-motion`.
- Never block the UI on the network; every fetch has a timeout and a quiet failure state. No secrets, no trackers.
- Speech: anything spoken must also be visible on screen. Do not chatter: speak only what the user asked for or what is
  genuinely important (a chain control, a severe weather warning), and give each spoken item a stable `id` so it is not
  repeated. Respect `settings.narr` (narration off = no automatic speech).
- iOS: audio and speech only start inside a user gesture; call `api.voice.unlock()` in click handlers that speak.
- Text style for the UI and spoken lines: plain, warm, specific, no exclamation marks except real celebrations (bingo,
  badges), no em dashes.

## Rides (js/ride.js)

Eight original vehicles drawn in SVG (compact car, camper van, pickup truck, convertible, motorhome, motorcycle, EV hatchback,
family bus), each in eight paint colours, with an optional driver badge (one emoji or up to two letters, drawn as the driver's
face) and a nickname (up to 20 characters). The saved ride lives in `api.store` under `ride` as `{kind, color, badge, name}`
(`kind` and `color` are ids from `api.ride.list()`; anything invalid falls back to the defaults, so a bad value can never
break the art). The art uses literal fills in a 120 x 80 box facing right, so it works as a plain SVG string everywhere,
including as a `data:` URL on a canvas (the passport share card), where CSS variables do not reach. `facing: "left"` mirrors
the body, never the badge text.

```js
api.ride = {
  get(),          // {kind, color, badge, name}  (a copy)
  svg(opts),      // <svg> element, or markup with {markup: true}. opts: kind, color, badge, name (default: the saved ride),
                  //   size (px width; height is 2/3), facing "right"|"left", rotate (deg), zz (default true: the hidden sleepy "z z"),
                  //   label (accessible name; without it the picture is aria-hidden)
  list(),         // {kinds: [{id, name}], colors: [{id, name, hex}]}
  set(patch),     // validated merge, saved, emits "ride"; returns false when nothing changed
  open(),         // opens the picker (#rideSheet)
  state(),        // "moving" | "idle" | "sleepy"
  sleepAfterMs,   // how long a stop lasts before the ride dozes (60000; tests lower it)
}
```

Where it shows: `#rideSlot` on the Drive sign (a 46 px button that opens the picker), `#rideRow` in Settings > Display, the
`#rideSheet` picker, the Map tab's position marker (map.js), the passport header and the trip share card (trip.js). Animation
is plain CSS on classes the host element carries: `ride-moving` (bounce, turning wheels), `ride-idle`, `ride-sleepy` (shut
eyelid on the headlight, floating "z z"); `prefers-reduced-motion` turns every animation off and the states still read from the
art. "Moving" means GPS or demo with speed of at least 3 mph; "sleepy" means tracking is off, or it has been stopped for a
minute. The first-run invitation ("Pick your ride? It rides along on the map." with Pick / Not now) appears once, under the
sign, only while the car is not moving and no sheet is open; the flag is `rideInvited` in the store. It is not modal and
takes no focus.

map.js uses `api.ride` if it is there: the "you" marker becomes the ride, facing left or right by the heading (`S.heading`
in GPS mode, else the road bearing plus the direction) and tilted at most about 40 degrees, so it is never upside down; without
ride.js the old dot and arrow stay. trip.js adds the ride and nickname to the passport header (`.pp-ride`) and draws the ride
in the sign's bottom right corner of the share card (`addRide`, through an `Image` from a `data:` URL, with a timeout; the
card is unchanged if that fails).

## The 3D map (js/map3d.js)

map.js adds a "3D" button as the last button of the map's zoom group. Tapping it injects the MapLibre stylesheet, `css/map3d.css`
and the MapLibre script (`vendor/maplibre/`, pinned in `vendor/maplibre/VERSION`) and calls `open(api, host, {onExit})`; none of
that is loaded at start-up or precached in `sw.js` SHELL (the worker's network-first rule keeps a copy after first use). `open` resolves `true` when the first map tile arrives and `false` when 3D
cannot run: no WebGL, the script or the style failed to load, or no tile arrived within 12 seconds (single failed tiles on
the road are ignored). map.js then shows "The 3D map needs a connection and 3D graphics. Here's the regular map." and the 2D map is
back; `close()` runs `map.remove()` and also happens when you leave the Map tab or tap 3D again. In the test suite every outside
host is blocked, so the 3D view always lands in that fallback (with or without WebGL).

What it draws: OpenFreeMap's `liberty` style (darkened colour by colour at night, since MapLibre has no dark switch), Terrarium terrain from
`s3.amazonaws.com/elevation-tiles-prod` (exaggeration 1.4) with a hillshade and sky, the I-5 line from `data.ROUTE` with a glow,
landmark pins (a circle layer in four tiers by zoom; the closest-spaced tier only appears when zoomed in; tap one for
`api.ui.placeSheet`), and the ride as a MapLibre marker standing on a ground marker (`rotationAlignment: "map"`) that points
the way you are heading. Camera: pitch 60, zoom about 12, following the car with the bearing set to the heading while moving;
dragging stops following and shows "Follow me". "Fly the road" glides the camera along the next 30 miles in the travel direction
in about 26 seconds (a Stop button flies back to the car; with `prefers-reduced-motion` it jumps to the stretch ahead instead).
Attribution is drawn by the module itself: "© OpenStreetMap contributors, OpenFreeMap · Terrain: Mapzen/AWS Terrain Tiles". Colours come from the app's tokens read with `getComputedStyle` (MapLibre paint cannot read CSS variables).

A test page can load `../index.html` in an iframe, then drive it through `iframe.contentWindow.I5BUDDY.api`
(for example `api.setPosition(740, {dir: "N", speed: 65, jumped: true})`, `api.ui.go("map")`, `api.S.mode = "demo"`).
`python3 tools/run_tests.py [--quick] [--only NAME]` runs every page in its SUITE list in headless Chrome. `tools/test-ride.html` (scenes art, picker, invite, moving, motion, passport) covers the rides; `tools/test-map.html?scene=ride` and `?scene=threed` cover the ride marker and the 3D button's fallback.
`tools/test.html` holds the geometry tests: California exit numbers, and places in Oregon and Washington must come out
off the road (they are checked against their own exit numbers when the build covers them). `tools/e2e.html` drives
fake GPS tracks through the app, including across the Oregon line and into Mexico. Both must keep saying ALL PASS, and
both read the road from the data, so they also pass with `SCOPE = ["CA", "OR", "WA"]`. Use California miles in
tests (0 to 797); a test that needs a place past an end should get it from the data (`ROUTE`, `MAX_M`), not a
hard-coded Oregon mile.
